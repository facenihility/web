工业智算网 · 通算协同调度平台 —— 使用说明
================================================================

目录里有什么
----------------------------------------------------------------
  工业智算网-通算协同调度仿真平台.html         原始纯前端版（双击就能用，无需任何环境）
  工业智算网-通算协同调度仿真平台-后端版.html    后端驱动版（由后端托管打开时自动接管）
  启动后端.cmd                              一键启动后端服务

  .test\                                    前端回归脚本（与历史基线逐字节比对用）

只想看界面 → 会（离线也能跑）
  直接双击「工业智算网-通算协同调度仿真平台.html」。
  这是纯前端单文件应用，用页面内置的 v1 标定版引擎跑仿真。

想用后端（推荐，功能全）
  1) 双击「启动后端.cmd」，等待出现启动信息（默认端口 8787）
  2) 浏览器打开  http://127.0.0.1:8787/
     · 顶部状态条：引擎 / 模型 / 在环模式 / 设备数 / 推流频率
     · 右下角徽标：切换「后端引擎」与「本地引擎」
     · 「模型与实验」卡片：一键跑 AI vs 基线的全场景对照实验
     · 「模型与实验」卡片底部：节点权重输入框（见下）

权重：由算法动态分配（不需要你设定）
  节点权重不是常数，算法每个控制周期根据系统实时状态自己算：
     · 压力 p = 利用率 + 0.15×归一化积压；取全网节点平均作为基准
     · 压力高于全网的节点自动降权（少接活）、低于的自动提权（多接活）
     · 再叠加"质量学习"：按实测服务质量（相对违约率 + 按任务截止归一化的时延）
       给出长期偏好，表现持续更好的节点权重更高
     · 全网均衡时权重自动回到 1.0 —— 此时模型精确退化为不加权重的标定版
  在「算力节点负载」卡片里可以看到每个节点的 算法权重（绿=被提权/红=被降权）与 压力。
  实测：持续压热某节点（利用率 97%）→ 其权重降到下限 0.60，空闲节点升到 1.53。

  上面的四个输入框是**可选的先验偏置**（默认 1.0 = 完全交给算法）：
  留空/不动就不用管它；想人为让某节点多扛一点，填个数（0.1~4.0）再点「应用先验偏置」。
  「清除偏置」恢复为完全由算法分配。

  效果（6 场景 × 120s，两个随机种子）：带动态权重比不带更优
  （−120.56 vs −119.44；−97.37 vs −96.72），且六个场景无一劣于静态规则基线。

没有硬件时，先跑通硬件在环全链路
  另开一个终端（后端保持运行），在本目录执行：
      python -m backend.tools.hw_device_sim --duration 30 --verbose
  模拟 7 台设备（2 台边缘盒子、2 台交换机、相机 / AGV / 机器人控制器）上报遥测与真实任务，
  并领取后端下发的调度指令。页面「硬件在环」卡片能看到设备列表、实测值、事件流。
  模式建议先 shadow（只对照不干预），确认量纲正确后再切 hil（实测覆盖仿真）。

接真实硬件
  接口契约（可直接发给硬件方）：  http://127.0.0.1:8787/api/hw/schema
  遥测上行：HTTP POST /api/hw/telemetry  ·  UDP 8790  ·  TCP 8791
  决策下行：GET /api/hw/commands 长轮询  →  POST /api/hw/ack 确认
  参考实现：backend\tools\hw_device_sim.py（同时就是接入模板）

跑一遍全部验证（约 1 分钟）
      python backend\tests\run_all.py
  9 组回归：引擎一致性(JS↔Python) / 前端引擎逐字节回归 / 渲染冒烟 14 项 /
  后端接口 40 项 / 硬件在环 45 项 / 节点权重与智能分配 30 项 /
  页面集成 28 项 / 模型门禁 / 前端静态校验

环境要求
  · 看界面：任意现代浏览器，零依赖
  · 跑后端：Python 3.8+（仅标准库，不需要 pip install 任何东西）
  · 跑前端回归脚本：Node.js（可选；只有 .test\ 下的两个脚本和一个测试用得到）
